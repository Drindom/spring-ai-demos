一、什么是检索增强生成

检索增强生成（Retrieval Augmented Generation，简称 RAG）是一种
将信息检索与大语言模型生成能力相结合的技术方案。大语言模型虽然
在自然语言理解和生成方面表现优异，但它的知识截止到训练数据为止，
无法回答关于企业私有数据、最新资讯或领域专有知识的提问，还可能
出现"幻觉"问题，即一本正经地编造不存在的答案。

RAG 的基本思路是：在模型回答问题之前，先从外部知识库中检索出与
用户问题相关的文档片段，把这些片段作为上下文拼接到提示词中，
再让模型基于这些上下文生成答案。这样一来，模型不再依赖自身记忆，
而是以检索到的真实资料为依据，显著提升了回答的准确性、时效性
和可解释性。

二、RAG 的典型工作流程

一个标准的 RAG 系统包含两个阶段：知识入库阶段和问答阶段。

在知识入库阶段，系统需要完成数据提取、文本转换、向量化存储
三个步骤，也就是常说的 ETL 流程。数据提取负责从 PDF、Word、
纯文本、网页等不同来源中读取内容；文本转换负责对长文档进行
清洗和切分，把文档拆分成大小合适的片段；向量化存储负责调用
嵌入模型把每个片段转换成向量，并写入向量数据库，同时保留
文档来源、标题等元数据信息。

在问答阶段，系统接收用户问题后，先对问题进行向量化，然后在
向量数据库中执行相似度检索，找出与问题最相关的若干文档片段，
再将片段与原始问题一起组装成提示词发送给大语言模型，最后把
模型生成的答案返回给用户。

三、Spring AI 中的相关组件

Spring AI 为 RAG 提供了开箱即用的支持，核心概念包括
Document、DocumentReader、DocumentTransformer、DocumentWriter、
VectorStore 和 Advisor。

Document 是 RAG 流程中传递的基本数据单元，包含正文文本、
元数据字典以及可选的图片、音视频等附加内容。DocumentReader
负责从各种来源读取原始文档，例如读取 PDF 的
PagePdfDocumentReader、读取纯文本的 TextReader、读取 JSON
的 JsonReader 等。DocumentTransformer 负责对文档做加工，
最常用的是文本分割器，如 TokenTextSplitter 按 token 数量
切分、ParagraphTextSplitter 按段落切分。DocumentWriter
负责把处理好的文档写入存储，VectorStore 就是文档的最终
去处，它内部维护向量索引，并提供相似度检索方法。

Advisor 是 Spring AI 提供的拦截器机制，可以在调用模型前后
注入逻辑。RAG 场景下最常用的是 QuestionAnswerAdvisor，
它会自动完成"检索文档、拼接上下文、调用模型"的完整流程，
开发者只需要把 VectorStore 交给它即可。此外，
RetrievalAugmentationAdvisor 提供了更细粒度的模块化组装
方式，支持查询改写、查询扩展、文档重排序等高级功能。

四、一个最简单的用法示例

假设我们已经把企业知识库的文档切分并向量化存储到了
VectorStore 中，那么启用 RAG 只需要在构建 ChatClient 时
挂载一个 QuestionAnswerAdvisor，代码如下所示：

ChatResponse response = ChatClient.builder(chatModel)
    .build()
    .prompt()
    .advisors(QuestionAnswerAdvisor.builder(vectorStore).build())
    .user("我们公司的年假政策是什么？")
    .call()
    .chatResponse();

其中 vectorStore 是注入的 VectorStore 实例。默认情况下
QuestionAnswerAdvisor 会对向量库中所有文档做相似度检索，
可以通过 SearchRequest 配置相似度阈值和返回条数，例如
把阈值设为 0.8、只返回最相关的 6 条。还可以通过过滤器
表达式按元数据筛选，比如只检索"分类等于人事制度"的文档。

五、常见问题与最佳实践

第一个常见问题是检索不到相关内容。这通常是因为文档切分
粒度过大或过小，导致片段语义不完整，或者嵌入模型与文档
语言不匹配。建议先检查片段是否保留了完整语义，再确认
嵌入模型是否支持中文。如果知识库包含多种语言，可以考虑
使用翻译查询转换器把用户问题统一翻译后再检索。

第二个常见问题是答案不准确。可以从三个方面排查：一是
向量检索的相似度阈值设置过低，混入了无关文档；二是
提示词模板没有明确要求模型只依据上下文回答；三是
检索结果没有按相关性重排序，相关文档被淹没在噪声里。
使用 DocumentPostProcessor 对检索结果做重排序或压缩，
可以有效提升答案质量。

第三个常见问题是对检索结果的筛选能力不足。在多租户或
多业务线的场景下，一定要利用元数据过滤，把检索范围
限制在当前租户或当前业务域，否则会出现跨部门泄露
敏感信息的问题。

总体而言，RAG 的调优是一个系统性工作：入库阶段要关注
文档清洗与分块策略，检索阶段要关注阈值、topK 与过滤
条件，生成阶段要关注提示词模板与后处理。把这几个环节
逐个验证清楚，就能搭建出一个可靠的企业级问答系统。
